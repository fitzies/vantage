# Integrating with Vantage

A guide for developers wiring an application to a self-hosted Vantage
instance. Replace the example host below with the URL provided by the
instance operator.

Vantage is a self-hosted, multi-project analytics service. Apps push
events at it; nothing reads back. This doc is for the **app side** —
what to install, what to configure, what to send. Nothing here touches
the Vantage server itself.

## What you need before you start

Two things, both from whoever runs the Vantage instance:

1. **Endpoint URL** — for example, `https://vantage.example.com/api/events`.
2. **Write key** — looks like `vntg_pk_<32 hex chars>`.

The write key is a **public identifier**. It identifies a project; it does
not authorize a user or grant dashboard access. It is designed to ship in
client bundles, but anyone who obtains it can submit events and pollute that
project's analytics. Do not treat it as an access-control secret.

## Getting a write key

Two ways. Pick whichever; both produce the same artifact.

### From the dashboard (recommended)

1. Open https://vantage.example.com.
2. Sign in with your Vantage account.
3. From the dashboard, press `p` or `⌘K` to open the project switcher.
4. Click **"+ New project"** at the bottom.
5. Enter a slug (lowercase, dashes only, e.g. `marketing-site`) and an
   optional display name.
6. **Copy the write key now.** The key is stored in the DB but never
   echoed back from the API or the UI again.

### From the CLI (operator-side)

From inside the Vantage repo:

```bash
pnpm tsx scripts/seed-project.ts <owner-email> <slug> "Display Name"
# e.g.
pnpm tsx scripts/seed-project.ts owner@example.com marketing-site "Marketing Site"
```

Same output: a `vntg_pk_…` printed once.

## The capture endpoint

One POST. That's the entire integration surface.

```
POST https://vantage.example.com/api/events
Headers:
  content-type: application/json
  x-vantage-key: vntg_pk_…
Body:
  { "event": "...", ... }            # single event
  or
  { "events": [ { ... }, { ... } ] } # up to 100 per request
```

A `204 No Content` means the batch landed. Anything else is a problem —
see [Errors](#errors).

CORS is open (`Access-Control-Allow-Origin: *`) so it works from any
browser origin without extra setup.

### Wire format

```ts
{
  event: string,              // required, ≤256 chars. Conventionally snake_case.
  event_id?: string | null,   // ≤128. Client idempotency key for retries/offline queues.
  user_id?: string | null,    // ≤256. Stable id for a signed-in user.
  anon_id?: string | null,    // ≤128. Per-device id, generated by you.
  session_id?: string | null, // ≤128. Tab/session-scoped id.
  timestamp?: string | number,// ISO 8601, epoch ms, or epoch seconds.
                              // Server clamps ±5min / -7d. Defaults to server now.
  url?: string | null,        // ≤2048
  referrer?: string | null,   // ≤2048
  user_agent?: string | null, // ≤1024. Server falls back to request UA if omitted.
  props?: Record<string, unknown>, // free-form jsonb, ≤32 KB serialized
}
```

### Limits

| Limit              | Value             |
| ------------------ | ----------------- |
| Total request body | 256 KB            |
| `props` per event  | 32 KB serialized  |
| Events per request | 100               |
| `event` length     | 256 chars         |
| `event_id` length  | 128 chars         |

If you exceed these, the request fails fast (413 / 400) — events
aren't silently truncated.

### Authenticating the request

Two ways to send the write key:

- **`x-vantage-key` header** — preferred. Use this from `fetch` / `XHR` /
  `curl`.
- **`key` field inside the JSON body** — fallback. Required when using
  `navigator.sendBeacon`, which can't set custom headers.

If both are present, the header wins.

## Path 1: Next.js (App Router) — recommended

Use the `@ojflabs/vantage` npm package. It ships a React/Next provider
that auto-fires `$pageview` on every App Router navigation, plus the
core `track / identify / page / reset` API.

### 1. Install

```bash
pnpm add @ojflabs/vantage
```

### 2. Set env vars

```bash
# .env.local
NEXT_PUBLIC_VANTAGE_PROJECT=<slug>
NEXT_PUBLIC_VANTAGE_WRITE_KEY=vntg_pk_…
```

The `NEXT_PUBLIC_*` prefix is intentional — these ship to the browser
by design. The write key is public; the project slug is just a label.

### 3. Mount the provider in `app/layout.tsx`

```tsx
import { VantageProvider } from "@ojflabs/vantage/react";

const VANTAGE_PROJECT = process.env.NEXT_PUBLIC_VANTAGE_PROJECT ?? "";
const VANTAGE_WRITE_KEY = process.env.NEXT_PUBLIC_VANTAGE_WRITE_KEY ?? "";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        {VANTAGE_PROJECT && VANTAGE_WRITE_KEY ? (
          <VantageProvider
            project={VANTAGE_PROJECT}
            writeKey={VANTAGE_WRITE_KEY}
            endpoint="https://vantage.example.com/api/events"
          />
        ) : null}
        {children}
      </body>
    </html>
  );
}
```

The conditional render lets dev environments without keys boot cleanly
instead of crashing.

### 4. Track custom events

Anywhere in a client component:

```tsx
"use client";
import { track } from "@ojflabs/vantage";

export function CTA() {
  return (
    <button onClick={() => track("cta_clicked", { variant: "hero" })}>
      Sign up
    </button>
  );
}
```

### 5. Tie events to a signed-in user

After login resolves:

```ts
import { identify, reset } from "@ojflabs/vantage";

// On login success
identify(user.id, { email: user.email });

// On logout
reset();
```

`identify()` automatically stamps `previous_anon_id` onto the next
event so the pre- and post-login sessions can be stitched together at
query time.

## Path 2: Browser (any framework)

Same npm package, same API, but you call `init()` yourself instead of
mounting the React provider.

```ts
import { init, track, identify } from "@ojflabs/vantage";

init({
  project: "marketing-site",
  writeKey: "vntg_pk_…",
  endpoint: "https://vantage.example.com/api/events",
});

track("signup_clicked", { plan: "pro" });
```

The tracker buffers events (1s window or 20-event cap), force-flushes
on tab hide, and falls back to `sendBeacon` so you don't lose pageviews
on navigation.

If you can't add a dependency, paste this ~30-line tracker into your
app instead. It does the essentials:

```ts
// vantage-tracker.ts
const ENDPOINT = "https://vantage.example.com/api/events";
const WRITE_KEY = "vntg_pk_…";

let queue: unknown[] = [];
let timer: ReturnType<typeof setTimeout> | null = null;

function getAnonId(): string {
  let id = localStorage.getItem("vntg_anon");
  if (!id) {
    id = crypto.randomUUID();
    localStorage.setItem("vntg_anon", id);
  }
  return id;
}

function flush(unloading = false) {
  if (queue.length === 0) return;
  const events = queue;
  queue = [];
  if (timer) { clearTimeout(timer); timer = null; }

  const body = JSON.stringify({ key: WRITE_KEY, events });

  if (unloading && "sendBeacon" in navigator) {
    navigator.sendBeacon(ENDPOINT, new Blob([body], { type: "application/json" }));
    return;
  }

  fetch(ENDPOINT, {
    method: "POST",
    keepalive: true,
    headers: { "content-type": "application/json", "x-vantage-key": WRITE_KEY },
    body,
  }).catch(() => { /* analytics shouldn't break the app */ });
}

export function track(event: string, props?: Record<string, unknown>) {
  queue.push({
    event,
    anon_id: getAnonId(),
    timestamp: new Date().toISOString(),
    url: location.href,
    referrer: document.referrer || null,
    user_agent: navigator.userAgent,
    props,
  });
  if (queue.length >= 20) flush();
  else if (!timer) timer = setTimeout(flush, 1000);
}

addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") flush(true);
});
addEventListener("pagehide", () => flush(true));
```

## Path 3: Backend / mobile / CLI (raw HTTP)

No SDK. Just POST.

### curl smoke test

```bash
curl -i -X POST 'https://vantage.example.com/api/events' \
  -H 'content-type: application/json' \
  -H 'x-vantage-key: vntg_pk_…' \
  -d '{
    "event": "smoke_test",
    "user_id": "u_42",
    "props": { "source": "curl" }
  }'
```

A working call returns `HTTP/1.1 204 No Content`.

### Node / TypeScript

```ts
async function track(event: string, props?: Record<string, unknown>) {
  await fetch("https://vantage.example.com/api/events", {
    method: "POST",
    headers: {
      "content-type": "application/json",
      "x-vantage-key": process.env.VANTAGE_WRITE_KEY!,
    },
    body: JSON.stringify({ event, props }),
  });
}

await track("order_placed", { order_id: "ord_123", total_cents: 4200 });
```

Use `keepalive: true` on `fetch` if you're calling from short-lived
serverless handlers and don't want to await the response.

### Python

```py
import os, requests

requests.post(
    "https://vantage.example.com/api/events",
    headers={
        "content-type": "application/json",
        "x-vantage-key": os.environ["VANTAGE_WRITE_KEY"],
    },
    json={"event": "order_placed", "user_id": user.id, "props": {"total_cents": 4200}},
    timeout=2,
)
```

### Mobile: Swift iOS

Use the Swift package in `sdks/vantage-swift`.

```swift
import Vantage

Vantage.configure(
    endpoint: URL(string: "https://vantage.example.com/api/events")!,
    writeKey: "vntg_pk_…",
    project: "my-ios-app"
)

Vantage.screen("Welcome")
Vantage.track("onboarding_step_completed", [
    "step": "permissions",
    "step_index": 2
])
Vantage.identify("user_123")
```

The Swift SDK emits `app_first_open` once per install and `app_open` on
configure, persists `anon_id`, batches/offline-queues events, attaches
mobile metadata, and sends `event_id` for retry dedupe.

### Mobile: Expo / React Native

Use `@ojflabs/vantage-expo`.

```ts
import AsyncStorage from "@react-native-async-storage/async-storage";
import Constants from "expo-constants";
import * as Device from "expo-device";
import * as Localization from "expo-localization";
import { AppState, Platform } from "react-native";
import { handleAppStateChange, init, screen, track } from "@ojflabs/vantage-expo";

await init({
  project: "my-expo-app",
  writeKey: "vntg_pk_…",
  endpoint: "https://vantage.example.com/api/events",
  storage: AsyncStorage,
  context: () => ({
    platform: Platform.OS,
    appVersion: Constants.expoConfig?.version ?? null,
    buildNumber: Platform.OS === "ios"
      ? Constants.expoConfig?.ios?.buildNumber ?? null
      : Constants.expoConfig?.android?.versionCode?.toString() ?? null,
    osVersion: Device.osVersion ?? null,
    deviceModel: Device.modelName ?? null,
    locale: Localization.getLocales()[0]?.languageTag ?? null,
  }),
});

AppState.addEventListener("change", (state) => void handleAppStateChange(state));

await screen("Welcome");
await track("onboarding_started");
await track("onboarding_step_completed", { step: "permissions", step_index: 2 });
```

## Identity

Vantage doesn't run a separate identities service. The convention:

- **Anonymous user** — generate an `anon_id` once per device, persist
  it, send it on every event.
- **Signed-in user** — set `user_id`. Send it on every event from then
  on.
- **The transition** — on the event right after login, also include
  `props.previous_anon_id` set to the device's old `anon_id`. This is
  the breadcrumb that lets queries stitch the pre-login session to the
  user.

The `@ojflabs/vantage` `identify(userId)` call does this automatically.
Rolling your own (e.g. on a backend or mobile)? Do the same:

```ts
// just after login succeeds
track("signup_completed", {
  // ...your normal props
  previous_anon_id: anonIdBeforeLogin,
});
// from now on, send user_id on every event
```

## Naming conventions

Pick a style and stick with it. The project uses:

- `snake_case` for event names (`order_placed`, not `OrderPlaced`).
- `$`-prefix for system events emitted by the tracker (`$pageview`,
  `$identify`). Avoid `$` in your own event names.
- **Stable names.** Renaming an event breaks every historical query
  that references it. There are no migrations — the cost of a rename
  is paid in dashboards, forever.

## Verifying events landed

```bash
# 1. Send one
curl -X POST 'https://vantage.example.com/api/events' \
  -H 'content-type: application/json' \
  -H 'x-vantage-key: vntg_pk_…' \
  -d '{"event":"smoke","props":{"hello":"world"}}'

# 2. Watch the dashboard
open https://vantage.example.com/dashboard
```

The new project shows up in the project switcher with its 24h count
and a live rate. The "stream" pane lists each event as it lands. You
should see your `smoke` event within a second or two.

## Errors

The endpoint returns JSON errors of the form `{ "error": "<code>" }`:

| Status | Code                  | Cause                                     |
| ------ | --------------------- | ----------------------------------------- |
| 400    | `invalid_body`        | Body wasn't readable as text              |
| 400    | `invalid_json`        | Body wasn't valid JSON                    |
| 400    | `invalid_schema`      | Failed schema validation (see `message`)  |
| 401    | `missing_write_key`   | No `x-vantage-key` header and no `key` in body |
| 403    | `unknown_write_key`   | Key doesn't resolve to a project          |
| 413    | `payload_too_large`   | Body exceeded 256 KB                      |
| 413    | `props_too_large`     | One event's `props` exceeded 32 KB        |
| 500    | `ingest_failed`       | Server-side problem — retry               |

Treat 4xx as "your client is wrong, fix it" and 5xx / network errors
as "retry once, then drop." Don't retry forever — analytics events
shouldn't hold up the user-facing thread.

## Things to avoid

- **Don't put PII in event names.** Names get listed in dashboards.
  Put identifiers in `props` or `user_id`, not `event`.
- **Don't send giant `props`.** 32 KB is the cap, but most events
  should be ≤1 KB. If you're tempted to dump a whole object, send a
  few key fields instead.
- **Don't track on the server *and* the client for the same action**
  unless you've decided which is canonical. Pick one per event.
- **Don't rename or delete events** without a real reason. Append-only
  is the contract.
- **Don't store the write key in a private/secret env var.** It's
  public by design — putting it behind a server-only var means your
  client never gets it.
